A weather API wrapper with caching and rate-limit handling, used by three indie apps in production.

Overview

Weathergram sits in front of a third-party weather provider and gives small indie apps a simpler, more reliable interface — with caching so nobody blows through their API quota.

The problem

A few indie developer friends kept hitting rate limits and inconsistent response shapes from raw weather APIs. Everyone was solving the same caching and normalization problem separately.

What I built

I built a FastAPI service that normalizes responses from multiple providers into one consistent schema, caches results in Redis with sensible TTLs based on forecast volatility, and gracefully falls back to a secondary provider if the primary one fails.

  • Unified JSON schema across two upstream weather providers
  • Redis caching tuned per endpoint (current vs. 7-day forecast)
  • Automatic failover to a backup provider
  • Simple API-key based rate limiting for consumers

What I learned

This project pushed me to think seriously about cache invalidation strategy and about designing an API contract that's stable even when the providers behind it change.
